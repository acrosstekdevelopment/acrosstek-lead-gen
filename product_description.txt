Step 6- purely backend

goal- find emails for the employees.
working-
    1. We first develop or search for company website url using the company name and company linkedin url. (needs to be researched to find the best way to do so)
    2. Then, we request a snov access token
    3a. Using this, we search for emails for the employees using snov api.
    3b. We send only the employees with status=NEW in table 2a and 2b to snov for scraping.
    4. snov works asynchronously for email search using api. Hence, if snov gives the status output= in_progress, we need to check again in 5 minutes if the status is still in_progress. We continue doing this until the status is not in_progress, and then add the email id to the email id column in table 2a and 2b. If the status is error, we update the status in table 2a and 2b to ERROR.
    5. once the emails are successfully scraped. i.e. all requests are out of in_progress status, we update the status in table 2a and 2b to EMAIL_FOUND for those employees where emails did get scraped, otherwise status=EMAIL_ERROR.

details-
1. snov access token-
    url- https://api.snov.io/v1/oauth/access_token
    method- POST
    body- 
        client_id=SNOV_CLIENT_ID
        client_secret=SNOV_CLIENT_SECRET
        grant_type=client_credentials
    
2. snov email search-
    url(read find emails from name and domain docs)- https://snov.io/api#EmailFinder
    method- POST
    search query-
    {

  "access_token": "access token that we found in previous step",

  "firstName": "first name from table 2a/2b",
  "lastName": "last name from table 2a/2b",
  
  "domain": "company domain that we generated in this step",
  "companyName": "company name from table 1a/1b"
}

3. snov output classification-
    applicable when status= completed (in snov output) - if yes then we check for the conditions below.
    if snov output status says in_progress, we check again in 5 minutes.
    if snov output status says error, we update the status in table 2a and 2b to EMAIL_ERROR.
    

https://snov.io/api#EmailFinder read find emails from name and domain docs for this.

    a. if smtp_status= unknown, then we proceed to check further conditions
    if smtp_status= valid, then we add the email to email id column in table 2a and 2b. and status=EMAIL_FOUND; No need to check for other conditions

    b. is_valid_format_check- if false, then we dont add the email id to the email id column in table 2a and 2b. and status=EMAIL_ERROR.
    if true, then we proceed to check the next condition

    c. is_disposable_check- if true, then we dont add the email id to the email id column in table 2a and 2b. and status=EMAIL_ERROR.
    if false, then we proceed to check the next condition

    d. unknown_status_reason= banned - add email to email id column in table 2a and 2b. and status=EMAIL_UNKNOWN.
    unknown_status_reason= catchall - add email to email id column in table 2a and 2b. and status=EMAIL_FOUND.
    unknown_status_reason= connection_error - add email to email id column in table 2a and 2b. and status=EMAIL_FOUND.
    unknown_status_reason= greylist - add email to email id column in table 2a and 2b. and status=EMAIL_FOUND.


Data Maturity-
2. if snov doesnt give an output or the output is empty(no error message as well), status in table 2a and 2b is updated to ERROR.
3. if snov gives an output, the status is updated to EMAILS_ENRICHED in table 1a and 1b for the company, if all employees scraping failed for a company, then status=ERROR in table 1a,1b, and for those employees where emails did get scraped, in table 2a and 2b , status=EMAIL_FOUND, otherwise status=EMAIL_ERROR - based on the snov output classification conditions.
4. System has to ensure that once a employee has been sent to snov for scraping, it shall never be sent again, hence all edge cases are to be kept in mind which might lead to status not getting changed after snov api is called for a particular employee. Only employees with status=NEW in table 2a and 2b are to be sent to snov for scraping.

error handling-
1. if snov outputs more than 1 email for 1 person, check snov output classification for both emails. whichever one is better is added to email id column in table 2a and 2b. How to tell which is better- 
    a. if one of the emails is valid and the other is not, then the valid one is better.
    b. if both are valid, then check for other conditions.
    c. check if_disposable field. if one is true and other is false, then the email with this status=true is discarded. if both are false, check for other conditions, if both are true, discard both of them and status=EMAIL_ERROR.
    d. check for is_valid_format_check. if both are false, then discard both of them and status=EMAIL_ERROR. if one is true and other is false, then the email with this status=true is better. if both are true, check for other conditions.
    e. if all above conditions led to this condition, that means both emails are of unknown status, then the first email is selected and 2nd one is discarded.
